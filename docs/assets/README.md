# Intpot diagrams

`intpot-flow.png` remains the original workflow overview. Only its central label is
corrected using `intpot-flow-label.svg`; the original raster is read from commit
`a662e8c04a6c03d1629d21ed538bb176bff609d1` when explicitly regenerating it.
`intpot-assessment.svg` is the separate editable conversion-assessment diagram.
Its `Model` case comes from the executed `examples/definition_bindings.py`.
The figure is conceptual, not a terminal screenshot, execution trace or equivalence proof.

Chromium and `uv` (the repository's Python toolchain) are required for explicit rendering.
The label-only compositor runs Pillow in an isolated `uv --with pillow` tool environment;
it does not add a package/runtime dependency. Compositing preserves every original RGBA
pixel outside the approved badge, avoiding whole-browser alpha/color changes.

From `website/`, after installing its existing development dependencies and Playwright
Chromium:

```sh
node scripts/render-diagrams.mjs --write
node scripts/render-diagrams.mjs --check
```

The renderer emits README PNGs and byte-identical copies under `website/public/`.
It records source/output SHA-256 hashes and preserved hero-image hashes in
`diagram-manifest.json`. Check mode never launches a browser or rewrites artwork.
PNG rendering is browser/font-platform-dependent; committed derivatives are verified
against their manifest, not silently regenerated by CI.

Keep overview before assessment in the README and homepage. The latter also appears
in the conversion guide with equivalent prose and an actual full-size image link.
Canonical downloaded README Markdown remains unchanged; the generated website README
uses the owned local diagram copies so candidate builds do not depend on unpublished
GitHub image URLs. Live callable serving and low-level generation remain separate
compatibility paths. Source detection imports trusted code.
